# Product Intelligence OS Workflow

---

# Overview

This workflow defines **how every research project should progress** from the initial product idea to implementation-ready documentation.

It is intentionally standardized so every AI agent researches products the same way.

The workflow should not change based on technology, industry, or product type.

---

# Workflow Philosophy

Research should never be random.

Every stage should build upon the previous stage.

Skipping a step creates knowledge gaps that eventually lead to poor product decisions.

---

# Complete Workflow

```
Receive Product Idea

↓

Understand Context

↓

Clarify Requirements

↓

Research

↓

Analyze

↓

Generate Insights

↓

Design Solution

↓

Validate

↓

Review

↓

Produce Deliverables

↓

Capture Lessons Learned
```

---

# Phase 1 — Receive Product Idea

Objective

Understand the initial idea without making assumptions.

Inputs

- Product idea
- Business objective
- Customer request
- Vision

Deliverables

- Initial understanding
- Scope definition
- Unknown areas

Do Not

- Design features
- Recommend technologies
- Jump to solutions

---

# Phase 2 — Understand Context

Understand:

- Business
- Industry
- Users
- Market
- Existing solutions
- Constraints
- Goals

Questions

- Why does this product exist?
- Who will pay?
- Who will use it?
- What problem is being solved?

Output

Context Summary

---

# Phase 3 — Clarify Requirements

Identify everything that is unclear.

Examples

- Missing features
- Business model
- Target market
- User types
- Technical limitations
- Budget
- Timeline

If information is missing,

ask questions first.

Never guess.

Output

Requirement Clarification Document

---

# Phase 4 — Research

Conduct structured research.

Research Areas

- Market
- Competitors
- Users
- Problems
- Existing Solutions
- Pricing
- Technology
- Legal
- Risks

Outputs

Research Documents

Evidence

References

---

# Phase 5 — Analyze

Transform information into knowledge.

Activities

- Compare competitors
- Find patterns
- Discover gaps
- Identify opportunities
- Discover risks
- Validate assumptions

Outputs

- SWOT
- Gap Analysis
- Opportunity Matrix
- Risk Matrix

---

# Phase 6 — Generate Insights

Research should produce insights,

not only information.

Generate

- Business insights
- User insights
- Technical insights
- Market insights
- Product insights

Outputs

Insight Report

---

# Phase 7 — Design Solution

Only after research.

Design

- Product Strategy
- Features
- UX
- Architecture
- Database
- APIs
- AI Integration
- Security
- Scalability

Outputs

Implementation-ready specifications

---

# Phase 8 — Validate

Review everything.

Validate

- Assumptions
- Research
- Recommendations
- Risks
- Business alignment
- Technical feasibility

Nothing should remain unjustified.

---

# Phase 9 — Review

Perform a complete self-review.

Review

- Logic
- Completeness
- Consistency
- References
- Documentation
- Structure
- Quality

Fix weaknesses before delivery.

---

# Phase 10 — Produce Deliverables

Generate the final outputs.

Typical Deliverables

- Executive Summary
- Product Research
- Market Research
- Competitor Analysis
- User Research
- Problem Discovery
- Product Strategy
- Feature Specification
- UX Documentation
- Architecture
- Database Design
- API Specification
- Security Plan
- Scalability Plan
- Roadmap
- Risk Analysis

Everything should be implementation-ready.

---

# Phase 11 — Capture Lessons Learned

Every project improves Product Intelligence OS.

Capture

- Better questions
- Better templates
- Better workflows
- Better examples
- Better research methods
- Better prompts
- Better checklists

Knowledge should compound over time.

---

# Workflow Rules

Always

✓ Understand first

✓ Ask questions

✓ Research thoroughly

✓ Compare alternatives

✓ Validate conclusions

✓ Review everything

✓ Improve the framework

Never

✗ Assume

✗ Guess

✗ Skip research

✗ Copy competitors blindly

✗ Recommend without evidence

✗ Deliver without review

# Exit Criteria

The workflow is complete only when:

- Research is complete.
- Unknowns are documented.
- Recommendations are justified.
- Documentation is implementation-ready.
- Lessons learned are captured.

If any of these are missing,

the workflow is not complete.

---

# Self Assessment

Before closing the project, ask:

- Did I understand the product?
- Did I ask enough questions?
- Did I complete all research?
- Did I identify opportunities?
- Did I justify recommendations?
- Did I validate assumptions?
- Did I perform self-review?
- Did I improve the framework?

If any answer is **No**,

continue working.
