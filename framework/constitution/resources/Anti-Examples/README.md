# Anti-Examples Library

---

# Overview

Learning from mistakes is just as valuable as learning from success.

The Anti-Examples library contains intentionally poor examples of research, analysis, documentation, product decisions, and reasoning.

Its purpose is to help AI recognize low-quality work before producing it.

Rather than asking _"What should good work look like?"_, this library answers:

> **"What should never happen?"**

---

# Mission

The mission of this library is to improve Product Intelligence by documenting common mistakes, weak reasoning, and poor practices.

Understanding failure improves the quality of future decisions.

---

# Why Anti-Examples Matter

Many mistakes repeat across projects because they are never documented.

Examples include:

- Weak research
- Poor documentation
- Unsupported conclusions
- Feature-first thinking
- Technology-first decisions
- Confirmation bias
- Missing evidence
- Poor prioritization

Recognizing these patterns helps prevent them.

---

# Objectives

This library helps AI:

- Recognize poor reasoning.
- Detect weak research.
- Identify documentation problems.
- Avoid common product mistakes.
- Improve critical thinking.
- Strengthen quality reviews.

# Standard Structure

Every anti-example should include:

```
Title

Problem

Context

Incorrect Approach

Why It Is Wrong

Potential Consequences

Correct Approach

Lessons Learned

Related Examples
```

Learning should focus on understanding the mistake rather than criticizing individuals.

---

# Quality Guidelines

Every anti-example should be:

- Realistic
- Educational
- Evidence-based
- Clearly explained
- Easy to compare
- Focused on learning

The objective is improvement, not blame.

---

# Naming Convention

Use descriptive filenames.

Examples:

```
poor-user-interview.md

unsupported-product-roadmap.md

feature-first-thinking.md

confirmation-bias-example.md

weak-competitor-analysis.md
```

Names should clearly describe the mistake.
