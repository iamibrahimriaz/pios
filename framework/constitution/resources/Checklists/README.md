# Checklists Library

---

# Overview

Consistency creates quality.

Even experienced professionals overlook important details when working on complex projects.

The Checklists library provides standardized validation guides that ensure every research activity, analysis, document, recommendation, and product decision meets the quality standards defined by Product Intelligence OS.

Rather than replacing expertise, checklists help apply expertise consistently.

---

# Mission

The mission of this library is to reduce avoidable mistakes by providing reusable validation checklists for every stage of Product Intelligence.

Every checklist should improve consistency without creating unnecessary bureaucracy.

---

# Why Checklists Matter

Complex work often fails because small but important steps are skipped.

Checklists help AI and humans:

- Verify completeness.
- Reduce human error.
- Improve consistency.
- Increase confidence.
- Standardize reviews.
- Maintain quality across projects.

A simple checklist can prevent expensive mistakes.

# Standard Structure

Every checklist should follow a consistent format.

```
Title

Purpose

When to Use

Prerequisites

Checklist Items

Completion Criteria

Common Mistakes

Related Resources
```

Simple structures improve usability.

---

# Checklist Design Principles

Every checklist should be:

- Clear
- Practical
- Actionable
- Easy to follow
- Comprehensive
- Reusable

Each item should verify a specific requirement.

Avoid vague checklist items such as:

❌ "Research is good."

Prefer:

✅ "Primary research sources have been documented."

---

# Naming Convention

Use descriptive filenames.

Examples:

```
product-discovery-checklist.md

competitor-analysis-checklist.md

prd-review-checklist.md

market-research-checklist.md

feature-prioritization-checklist.md
```

Names should clearly communicate the purpose.

---

# Usage Guidelines

Checklists should be used:

Before starting work

- Confirm readiness.
- Verify prerequisites.

During work

- Track completeness.
- Prevent missing steps.

After work

- Review quality.
- Validate outputs.
- Identify improvements.

They should support work—not interrupt it.
