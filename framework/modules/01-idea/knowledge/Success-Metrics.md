# Success Metrics

---

# What It Is

At this stage, a statement of **what would count** as success — not a target.

The distinction matters because module 01 has no baseline, no users and no data. It can say what
to look at. It cannot say what number to expect, and any number written here will be quoted
later as though it had a source.

| This module can | This module cannot |
| --- | --- |
| Name the observable outcome | Set a credible target for it |
| Say what would count as failure | Predict a rate |
| Identify who would need to change behavior | Say how many will |

---

# When It Applies

In Pass 3 (Locate) and Pass 6 (Bound). `12-metrics` does the real work: definitions, baselines,
targets, counter-metrics and instrumentation.

---

# How to Apply It Here

**Name the observable, and stop.** "Notes completed before the patient leaves" is enough. Adding
"in 80% of consultations" invents a figure that becomes a commitment.

**Say what would count as the idea not working.** This is more useful now than any success
figure, and it is what module 07 needs for its stop conditions:

| Weak | Useful |
| --- | --- |
| "Users love it" | "Clinicians go back to their old method within two weeks" |
| "Good adoption" | "Fewer than half the users who try it complete one consultation with it" |

**Prefer the user's outcome over the product's activity.** "Left the clinic on time" is the
outcome. "Used the product" is activity, and a product can be used heavily by someone it is
failing.

**Leave the metric to module 12.** This is a candidate, not a definition. Module 12 will require
a numerator, a denominator, a window, a population and exclusions — none of which needs settling
here.

---

# Where It Misleads

**A number written at this stage acquires authority it never earned.** Six weeks later nobody
remembers it was invented in the first hour, and the business model will have been built on it.
This is the same laundering problem the framework guards against everywhere; here it starts with
a plausible-looking percentage.

**Early metrics tend to measure the product's activity rather than the user's outcome**, because
activity is easier to imagine. Module 12's vanity check exists for exactly this.

**Success at this stage is not adoption.** For an idea, success is that the problem turned out to
be real and sharp. That is what modules 03 and 04 establish, and it is the only success available
before anything is built.
