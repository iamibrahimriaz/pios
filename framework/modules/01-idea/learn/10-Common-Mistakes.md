# Common Mistakes

---

# Overview

Every mistake below is individually defensible at the moment it is made. That is what
makes them recur. None of them look like errors — they look like momentum.

---

# 1. The Solution Stated as the Idea

**What it looks like.** "An AI assistant for accountants." "A marketplace for local
tradespeople."

**Why it is tempting.** It is how ideas actually arrive. Nobody has a problem first;
people have solutions and reverse-engineer the problem afterward.

**What it costs.** Module 04 later asks which ranked problem each feature traces to,
and the honest answer is that the feature came first. The trace is then constructed
backwards, which is undetectable in the document and fatal in the market.

**Instead.** Keep the solution — it is genuine signal about where you have been
looking — but write it as one line of the brief rather than as the brief.

---

# 2. The Market Named by Adjective

**What it looks like.** "Small businesses." "Modern teams." "Underserved creators."

**Why it is tempting.** Adjectives feel inclusive, and narrowing feels like giving up
addressable revenue.

**What it costs.** Module 02 cannot size an adjective. The gate there requires a
boundary — a country, a sector, a size band, a regulatory regime — and a run that
arrives without one either halts or invents the boundary silently, which is worse.

**Instead.** Name something you could count. "Single-handed general practices in
England" is a boundary. "Small healthcare providers" is a mood.

---

# 3. Buyer and User Assumed Identical

**What it looks like.** The brief says "users" throughout and never asks who signs.

**Why it is tempting.** In consumer products they genuinely are the same person, and
the habit transfers.

**What it costs.** Module 06 has to identify the payer, and if that question was never
asked, the pricing strategy is built for whoever the document happened to describe.
The most common form is a product delightful to the user and unpurchasable by the
person with the budget.

**Instead.** State it explicitly even when they are the same person. "Buyer and user
are the same" is a finding. Silence is not.

---

# 4. Assumptions Written as Facts

**What it looks like.** "Clinicians spend two hours a day on documentation."

**Why it is tempting.** Hedged prose reads as weak, and a brief full of `[assumption]`
tags looks like you have done no work.

**What it costs.** This is the failure the constitution exists to prevent. An
assumption that enters unlabeled is inherited by every downstream module as though it
were verified, and by module 07 it is load-bearing in a decision nobody remembers
making on it.

**Instead.** Tag it. `[assumption: needs validation]` is not an admission of laziness;
it is the input module 04's validation plan is built from. An untagged guess produces
no validation work, which is precisely why it survives.

---

# 5. Too Few Questions, Asked Too Politely

**What it looks like.** Five clarifying questions, all of which the operator can answer
comfortably, none of which could change the direction.

**Why it is tempting.** Questions that could invalidate the idea are unpleasant to ask
of someone who is excited about it — including yourself.

**What it costs.** The questions that were not asked become the assumptions that are
not tagged, and they surface in module 13 as an operating cost nobody planned for.

**Instead.** Include at least one question whose answer you would rather not hear. If
every question has a comfortable answer, the set is incomplete.

---

# 6. Scope Boundaries Left Open "For Flexibility"

**What it looks like.** No non-goals. Everything is potentially in scope.

**Why it is tempting.** Early commitment feels premature, and openness feels like
optionality.

**What it costs.** Module 07 must draw an MVP cut line, and a scope that was never
bounded has no natural place to cut. What emerges is the failure that module names
directly: **scope laundering** — everything stays in, described as phase one.

**Instead.** Write what is out. A boundary you can revise beats a boundary you never
drew.

---

# The Pattern

| Mistake | Underlying move |
| --- | --- |
| Solution as idea | Skipping the problem |
| Market by adjective | Avoiding a countable claim |
| Buyer assumed | Not asking who pays |
| Assumption as fact | Smoothing uncertainty |
| Polite questions | Protecting the idea |
| Scope left open | Deferring a decision |

Five of the six are the same instinct: **protecting the idea from contact with
anything that could reduce it.** The sixth is protecting yourself from a decision.
Both feel like care and both are expensive.

---

> **Mistakes Principle**
>
> None of these produce a bad document. They produce a confident one.
>
> The idea stage fails quietly, and the bill arrives four modules later — which is why
> it is worth recognizing these while they still cost nothing to fix.
