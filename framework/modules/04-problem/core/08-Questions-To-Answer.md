# Questions To Answer

---

# Overview

Most questions here are asked **about** each candidate problem, not once for the module.
Work them per problem, at least for everything that survives classification.

`NEEDS USER` questions cannot be answered by proxy research. Record them; do not answer
them. They become the validation plan.

---

# 1. Harvest

| # | Question | If unanswered |
| --- | --- | --- |
| 1.1 | Where does the current workflow break, stall, or annoy? | The richest source is unmined |
| 1.2 | Which job is served poorly today? | Gaps are invisible |
| 1.3 | Which step would they most want removed? | The sharpest candidate is missed |
| 1.4 | What do they complain about in reviews and forums? | Stated frustration unmined |
| 1.5 | What did they build a workaround for? | A gap with evidence attached is missed |
| 1.6 | What costs them time outside working hours? | Often the most painful and least reported |

---

# 2. Classification

Ask for every statement harvested.

| # | Question | Purpose |
| --- | --- | --- |
| 2.1 | Is there a cost when this is not solved? | No cost → preference, not problem |
| 2.2 | Why does this happen? | If there is an answer, this is a symptom |
| 2.3 | What is the problem underneath this symptom? | Carries the real problem forward |
| 2.4 | Would they pay to make this go away? | Tests whether the cost is felt |

> **2.1 is the preference filter.** "I wish it had dark mode" costs nothing when unmet.
> "I do notes at home after clinic" costs unpaid hours. Only one is a problem.

---

# 3. Frequency

| # | Question | If unanswered |
| --- | --- | --- |
| 3.1 | How often does this occur? | Cannot score |
| 3.2 | Is it constant, periodic, or triggered by an event? | Severity is misjudged |
| 3.3 | Is frequency growing, stable, or shrinking? | Timing is invisible |
| 3.4 | Does frequency differ across the segment? | The prioritized segment may be atypical |

---

# 4. Severity

| # | Question | If unanswered |
| --- | --- | --- |
| 4.1 | What does one occurrence cost — time, money, risk, wellbeing? | No value case |
| 4.2 | Can that cost be quantified? | Module 06 cannot price the value |
| 4.3 | Who bears the cost — the user, their employer, their customer? | The payer may differ from the sufferer |
| 4.4 | What is the worst realistic outcome when this goes wrong? | Risk is understated |
| 4.5 | Is the cost visible to them, or absorbed unnoticed? | Invisible costs are hard to sell against |

> **4.5 matters commercially.** A cost people absorb without noticing is a hard sale,
> however real it is. Naming it early prevents surprise in module 06.

---

# 5. Current Workaround

| # | Question | If unanswered |
| --- | --- | --- |
| 5.1 | What do they do about this today? | The real competitor is unknown |
| 5.2 | How well does that work? | Score is wrong |
| 5.3 | What does the workaround itself cost? | The true baseline is missing |
| 5.4 | Why has nobody built something better? | The gap may not be real |
| 5.5 | Is there genuinely no workaround, and if so, why not? | Either very valuable, or not painful enough |

---

# 6. Evidence

| # | Question | If unanswered |
| --- | --- | --- |
| 6.1 | What specifically evidences this problem? | It belongs in the assumed list |
| 6.2 | Is that evidence observation, or opinion? | Weight is misassigned |
| 6.3 | Is the source self-selected? | Generalization is unsafe |
| 6.4 | How many independent sources describe it? | One echo is not corroboration |
| 6.5 | **NEEDS USER** — Would someone with this problem recognize my description? | Validation gap |

---

# 7. The Sharpest Problem

| # | Question | If unanswered |
| --- | --- | --- |
| 7.1 | Which problem scores highest? | No basis for choice |
| 7.2 | Is the highest scorer the one to build around? | The choice is unexamined |
| 7.3 | If not, why was it passed over? | The obvious objection is unanswered |
| 7.4 | Is this problem verified or assumed? | The roadmap cannot be planned |
| 7.5 | Why has nobody solved it? | The gap may be structural, or imaginary |
| 7.6 | Is this the root problem, or a consequence of one? | Risk of optimizing a symptom |
| 7.7 | If we solve only this, is the product worth using? | The MVP may not stand alone |

---

# 8. Root Cause

| # | Question | Purpose |
| --- | --- | --- |
| 8.1 | Why does this problem occur? | First level |
| 8.2 | And why does *that* occur? | Repeat until the answer stops being actionable |
| 8.3 | Where did the chain stop being actionable? | Marks the boundary of what can be built |
| 8.4 | Are we solving the root, or a symptom? | Must be a decision, not an oversight |
| 8.5 | If the root is outside our control, is solving the symptom still worthwhile? | Legitimate, when stated |

---

# 9. Contradicting Evidence

| # | Question | If unanswered |
| --- | --- | --- |
| 9.1 | What suggests this problem is not worth solving? | The adversarial pass was skipped |
| 9.2 | Has anyone tried to solve it and failed? | A paid-for lesson is ignored |
| 9.3 | Is the population that has this problem shrinking? | Timing risk invisible |
| 9.4 | Do people describe it as annoying but tolerable? | Urgency is overstated |

> **9.4 is the quiet killer.** A problem everyone agrees is annoying but nobody prioritizes
> fixing produces polite research interest and no sales.

---

# 10. Validation

| # | Question | If unanswered |
| --- | --- | --- |
| 10.1 | Which belief, if wrong, breaks the product? | Validation has no priority |
| 10.2 | What is the cheapest way to test it? | Effort is misallocated |
| 10.3 | How many people, and which ones? | The plan is not actionable |
| 10.4 | What result would invalidate it? | The test cannot fail, so it proves nothing |
| 10.5 | What result would stop this project? | Failure is never defined |

**10.4 is the test of a real test.** If no result would invalidate the assumption, the
proposed validation is theater.

---

# 11. Questions Needing a Real User

Record. Do not answer.

| # | Question |
| --- | --- |
| U1 | How often does this actually happen to you? |
| U2 | What does it cost you when it does? |
| U3 | What do you currently do about it? |
| U4 | Have you looked for a better way? What stopped you? |
| U5 | If this were solved, what would change for you? |
| U6 | Is this in your top three frustrations, or somewhere below? |

**U6 is the most valuable question in this list.** People will confirm almost any problem
is real. Far fewer will place it in their top three — and only top-three problems get
budget.

---

# 12. Questions the Agent Asks Itself

- Did I classify before scoring?
- Did I promote an assumed problem because the validated list looked thin?
- Is my sharpest problem the highest-scoring one, or the most interesting one?
- Did I score workarounds generously to make a problem look bigger?
- Am I solving a symptom and calling it a root?
- Would a practitioner recognize this as their actual pain?
- Does my validation plan contain a test that could actually fail?
- Have I defined what would stop this project?

---

# Anti-Patterns

| Anti-pattern | Example | Why it fails |
| --- | --- | --- |
| Preference as problem | "They want dark mode" scored alongside unpaid overtime | Dilutes the MVP |
| Symptom as problem | "Export takes four clicks" | Optimizes the wrong thing |
| Generous workaround scoring | "No good workaround" when a decent one exists | Inflates the score |
| Evidence by assertion | "Clearly this is painful" | Untagged, unverifiable |
| Unfalsifiable validation | "Talk to users about the problem" | No result could disprove anything |
| No stop trigger | Failure undefined | The project cannot end rationally |

---

> **Interrogation Principle**
>
> Everyone will agree your problem is real.
>
> The question that matters is whether it is in their top three — because
> only top-three problems get budget.
