# Best Practices

---

# 1. Run the Payback Arithmetic on the First Page

Before choosing a single channel: margin, payback period, ceiling, cost of one unit of the motion,
implied CAC.

Done first, it rules out whole categories of plan in five minutes. Done last, it becomes a
justification for a plan already written.

---

# 2. Ask the Operator for the Payback Period

One question: how long can you wait to recover the cost of acquiring a customer?

Without it the ceiling is arbitrary. With it, the ceiling is theirs — and a motion that fails
against it fails on their terms rather than the framework's.

---

# 3. Write the Citation Before the Channel Name

For each row, fill in "where the segment was observed" first, then name the channel.

Written in that order, the evidence chooses the channel. Written the other way, the channel goes
looking for evidence and usually finds something adjacent.

---

# 4. Take the Channel List From the Interviews, Not From Practice

Read `03-user`'s research for what these people read, attend, belong to and trust.

That list is short, unglamorous and correct. The generic channel list is long, familiar and
usually wrong for a specific professional segment.

---

# 5. Price the Test, Not the Campaign

Per channel: what does one test cost, and how long until it tells you something?

This is the only number in the section that is actually knowable, and it is the right basis for
choosing what to do first.

---

# 6. Define Activation as Something the User Would Describe as Useful

Write the event as the user would say it: "I got my first note saved against a real patient."

Written in system terms — "record created" — the event drifts toward whatever is easy to log, and
then the activation rate measures instrumentation rather than value.

---

# 7. Put the Migration Inside the Activation Flow

If the user must move data, retrain, or run two systems in parallel, that work happens **before**
they reach value.

Planning it as post-activation onboarding is the most common reason activation rates come in far
below target.

---

# 8. Name One Thing That Would Most Improve Activation

From the flow analysis in `10-execution`, not from general practice.

One specific change, identified from this product's own step count, is worth more than a list of
onboarding best practices.

---

# 9. Ask What the User Loses by Leaving

For each retention mechanism, answer in the user's terms: what do they lose?

If the answer is "nothing much", write that. A plan that admits weak retention can be fixed; one
that asserts strong retention cannot.

---

# 10. Put the Requirement Number Next to Every Retention Mechanism

Not a description of the feature — the requirement identifier from `08-product`.

An identifier can be checked. A description can be written for a capability that does not exist.

---

# 11. Write the Churn Early Warning, Not the Churn Rate

The rate is unknowable and will be invented. The behavior that precedes leaving is observable and
actionable.

Usage falling below a threshold, a specific feature abandoned, a support ticket of a particular
kind. Those can be watched from week one.

---

# 12. Draw the Loop, Then Try to Follow the Arrow Round

Literally trace it. Start at the input, move through the action to the output, and see whether the
thing you are holding at the end is the same kind of thing you started with.

Most diagrams fail this trace, and the failure is invisible until it is attempted.

---

# 13. Write "This Is a Funnel" When It Is

In those words.

It changes nothing about the quality of the business and everything about how the person funding
it plans for spend, hiring and valuation.

---

# 14. Ask What Makes the Second Turn Bigger

If nothing does, the mechanism sustains itself without compounding — which is worth knowing and
usually goes unsaid.

---

# 15. Name Ten Real People Before Writing Any Channel Strategy

Actual names where possible. Specific profiles otherwise: "the two-partner practice in «place»
that «detail»".

The exercise is short and it is the fastest way to discover that a plan is abstract.

---

# 16. Write Their Objection Before Writing the Pitch

From `05-competition`'s status quo analysis: why would they keep doing what they do now?

The pitch written afterwards addresses the real reason for no. The pitch written first addresses
features.

---

# 17. Say Whether the First Ten Are Customers or Subjects

Where the problem is assumed, the first ten are the validation sample.

Naming them as such keeps the first conversations honest — they are being asked whether the
problem is real, not being sold to, and those are different conversations that cannot both happen
at once.

---

# 18. Tag Every Rate as You Write It

Conversion, activation, churn, cycle time — each gets its tag and its basis in the same keystroke.

Retrofitted tags get attached to the numbers you remember inventing, which is never all of them.

---

# 19. Read the Plan as the Person Funding It

Which numbers would they treat as established? Which of those are assumptions?

Every gap is growth laundering, and this is the only reliable way to find it, because that reader
is the one the document was unconsciously written for.

---

# 20. Gate the Spending, Explicitly

Write the sequencing table with its conditions: before the first ten, before the first channel
test, before scale.

Where the problem is assumed, write that no acquisition spend happens before Milestone Zero. It is
one line, and it is where the framework's evidence position finally costs money.

---

# Anti-Practices

| Habit | Why it fails |
| --- | --- |
| Payback check last | Becomes a justification for the existing plan |
| Ceiling chosen without the operator | Arbitrary, and disputed later |
| Channel named before its evidence | The channel finds adjacent evidence |
| Generic channel list | Long, familiar, wrong for a specific profession |
| Pricing the campaign | The unknowable number replaces the knowable one |
| Activation in system terms | Measures instrumentation, not value |
| Migration after activation | Activation rates disappoint predictably |
| Retention as product quality | Nothing holds |
| Mechanism described, not identified | Written for capability that may not exist |
| Churn rate without early warning | Nothing to act on |
| Loop diagram never traced | Funnels pass as loops |
| Funnel drawn with a return arrow | Misrepresents the business to its funder |
| First ten as a market description | The plan stays abstract |
| Pitch before objection | Addresses features, not the real no |
| Selling to the validation sample | Two incompatible conversations at once |
| Tags added at the end | Some inventions keep their authority |
| Never reading it as the investor | Laundering survives |

# Self Assessment

- Did I run the arithmetic first?
- Did I ask the operator for the payback period?
- Did I write citations before channel names?
- Did the channel list come from the interviews?
- Did I price the test rather than the campaign?
- Would the user describe my activation event as useful?
- Is the migration inside the activation flow?
- Did I name the one change that would most improve activation?
- Do I know what a user loses by leaving?
- Does every mechanism carry a requirement identifier?
- Did I write the early warning instead of the rate?
- Did I trace every loop arrow round?
- Did I call the funnels funnels?
- Do I know what makes the second turn bigger?
- Can I name ten people?
- Did I write the objection before the pitch?
- Are the first ten subjects or customers?
- Is every rate tagged with a basis?
- Did I read it as the investor?
- Is the spending gated?

---

> **Practice Principle**
>
> Two practices here take five minutes and decide the most:
> the arithmetic on the first page, and tracing the loop arrow round.
>
> Both are mechanical, and both are usually skipped because the
> answer feels obvious before it is checked.
