# Questions To Answer

---

# Overview

This module asks fewer research questions and more **decision** questions than any other.

Most are answered by reasoning over what the research established. A significant minority
are **OPERATOR** questions, because they are commitments — of money, time and appetite —
that only the operator can make.

---

# 1. Inherited Position

| # | Question | If unanswered |
| --- | --- | --- |
| 1.1 | What is the sharpest problem, and is it verified or assumed? | Milestone Zero requirement unknown |
| 1.2 | Is the gap defensible? | The strategy has an unmeasured clock |
| 1.3 | Is the business viable, and under what conditions? | The chosen option may be unfundable |
| 1.4 | Did module 04 declare an evidence shortfall? | Validation may be skipped |
| 1.5 | What is the load-bearing assumption in the business model? | The main risk is unregistered |

---

# 2. Generating Options

| # | Question | Purpose |
| --- | --- | --- |
| 2.1 | What if we solved only the sharpest problem, completely? | The narrow-tool shape |
| 2.2 | What if we replaced the whole workflow? | The replacement shape |
| 2.3 | What if we sat on top of the incumbent instead of replacing it? | The layer shape |
| 2.4 | What if a person did this and software came later? | The service shape |
| 2.5 | What if we started with a different segment? | The sequencing shape |
| 2.6 | **Would each option produce a different first build?** | The genuine-difference test |
| 2.7 | **Could a competent person reasonably choose each one?** | The straw-man test |

> If 2.6 or 2.7 fails, the module has generated one option and some decoration.

---

# 3. Comparing

| # | Question | If unanswered |
| --- | --- | --- |
| 3.1 | Which option best solves the sharpest problem? | The primary criterion is unscored |
| 3.2 | Which fits the gap identified in module 05? | May target a served space |
| 3.3 | Which is most defensible? | The clock is not compared |
| 3.4 | Which supports the price from module 06? | May be unfundable |
| 3.5 | Which can be built by the assumed team? | May be undeliverable |
| 3.6 | Which reaches a paying customer soonest? | Learning speed ignored |
| 3.7 | **Which survives if the assumed problem turns out to be minor?** | Fragility invisible |
| 3.8 | How were the weights assigned? | Scoring is arbitrary |

---

# 4. Choosing

| # | Question | If unanswered |
| --- | --- | --- |
| 4.1 | Which option, and why? | No decision |
| 4.2 | **What do we lose by rejecting each other option?** | Rejected ideas return as features |
| 4.3 | What belief is this choice betting on? | The bet is implicit |
| 4.4 | What would make us choose differently? | No reversal condition |
| 4.5 | Is this choice reversible, and at what cost? | Commitment level unknown |
| 4.6 | **OPERATOR** — Is there an approach you would refuse? | Constraint discovered late |

---

# 5. The MVP Cut

| # | Question | If unanswered |
| --- | --- | --- |
| 5.1 | What is the smallest thing that solves the sharpest problem completely? | No anchor for the cut |
| 5.2 | **Can the primary persona complete the core job with only this?** | The MVP teaches nothing |
| 5.3 | What principle decides what is in? | The cut is arbitrary |
| 5.4 | What does the MVP prove? | Shipping produces no answer |
| 5.5 | **What does it deliberately not prove?** | The wrong conclusion gets drawn |
| 5.6 | What is the first thing to build within it? | Module 10 has no starting point |
| 5.7 | Which capability was hardest to cut, and why did it go? | The judgment is unrecorded |
| 5.8 | **OPERATOR** — Is this cut acceptable, or too narrow? | The commercial call is unmade |

> **5.5 is under-asked and expensive.** Teams ship an MVP, see weak adoption, and conclude
> the problem was not real — when the MVP never tested that at all.

---

# 6. Non-Goals

| # | Question | If unanswered |
| --- | --- | --- |
| 6.1 | Which capabilities are we not building? | Scope creeps |
| 6.2 | Which segments are we not serving? | Focus dissolves |
| 6.3 | Which real problems from module 04 are we not solving? | Exclusions look accidental |
| 6.4 | Which systems will we not integrate with? | Integration debt accrues |
| 6.5 | For each, what would make us reconsider? | Exclusions become permanent by default |

---

# 7. Risk

| # | Question | If unanswered |
| --- | --- | --- |
| 7.1 | What could make the product fail commercially? | Commercial risk unregistered |
| 7.2 | What could make it fail technically? | Technical risk unregistered |
| 7.3 | What could make it fail legally or regulatorily? | Compliance risk unregistered |
| 7.4 | What happens if the incumbent responds? | The most likely threat unplanned |
| 7.5 | For each risk, **what would we see first**? | The register is decorative |
| 7.6 | Which risks are we accepting rather than mitigating? | Acceptance is implicit |
| 7.7 | Which risk did I rate low because rating it high was uncomfortable? | Honest rating avoided |

---

# 8. Sequence

| # | Question | If unanswered |
| --- | --- | --- |
| 8.1 | **Is Milestone Zero required?** | Building may start on an untested belief |
| 8.2 | What does each milestone teach us? | Milestones are schedule entries |
| 8.3 | Which milestone is independently shippable? | No incremental value |
| 8.4 | What is the critical path? | Sequencing is arbitrary |
| 8.5 | **OPERATOR** — What timeline are you working to? | Sequence has no constraint |

**8.1 is answered yes whenever** the sharpest problem is assumed rather than verified, or
module 04 recorded a declared shortfall.

---

# 9. Stop Conditions

| # | Question | If unanswered |
| --- | --- | --- |
| 9.1 | What result would mean this should not continue? | The project cannot end rationally |
| 9.2 | What specific number or signal represents that? | The condition is unfalsifiable |
| 9.3 | Who decides, and when do they look? | Nobody owns the decision |
| 9.4 | **OPERATOR** — What would make you stop? | The real threshold is unknown |

---

# 10. For the Checkpoint

| # | Question | Purpose |
| --- | --- | --- |
| 10.1 | Can I state the proposal in one sentence? | The operator must be able to grasp it quickly |
| 10.2 | Have I stated what we are not doing? | Prevents later surprise |
| 10.3 | Have I named the load-bearing assumption? | The operator is betting on it too |
| 10.4 | Have I given options, or a conclusion? | A checkpoint with one option is a report |
| 10.5 | Have I said plainly where the foundations are weak? | Bad news must not be softened |

---

# 11. Questions the Agent Asks Itself

- Did I decide first and generate options afterward?
- Are two of my options there only to lose?
- Is my MVP minimal, or everything that scored well?
- If the assumed problem is minor, what survives of this strategy?
- If the incumbent ships this next quarter, what do we still have?
- Which risk rating did I soften?
- Am I asking for approval, or announcing a decision?

---

# Anti-Patterns

| Anti-pattern | Example | Why it fails |
| --- | --- | --- |
| Straw-man options | Two deliberately weak alternatives | The choice was pre-made |
| Same-shape options | Three feature scopes | No real alternative examined |
| Unrecorded rejections | Only the chosen option written up | Rejected ideas return unexamined |
| MVP by scoring | Everything above average included | No cut; no learning |
| Missing non-goals | Scope left open | Creep with no baseline |
| Uniform risk ratings | All medium | The register is ignored |
| No Milestone Zero | Building on an assumed problem | The failure this framework exists to prevent |
| Checkpoint as summary | "Here is what we decided" | Removes the operator's decision |

---

> **Interrogation Principle**
>
> Every question here that starts "what would make us stop" or "what do we lose"
> exists because nobody asks it once building has started.
