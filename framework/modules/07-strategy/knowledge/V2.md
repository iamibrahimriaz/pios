# V2

---

# What It Is

The horizon after the first sellable release — held as **directions with triggers**, not as scope.

By V2 the product will have real users, and real users invalidate plans. What can honestly be written now is the set
of candidate directions and the evidence that would select among them:

| Direction | Trigger that would select it |
| --- | --- |
| Second-ranked problem from `04-problem` | The first is solved and customers name it as the next cost |
| Second segment from `03-user` | The first segment is retained and the channel generalizes |
| Depth in the same problem | Usage data shows the current solution is incomplete in a specific way |
| Expansion capability | `06-business`'s upgrade path becomes real demand |
| Integration with the system of record | Switching cost or procurement demands it |

Each is a direction. None is a commitment.

---

# When It Applies

In Move 6 (Sequence), stated at the lowest fidelity of any milestone. The deferral ledger from Move 4 is its raw
material.

---

# How to Apply It Here

**Attach a trigger to every direction.** The trigger is what makes the roadmap a decision structure rather than a
schedule. Without it, V2 is chosen by whoever asks most persistently.

**Keep the fidelity honest and decreasing.** MVP is specified, V1 is gated, V2 is directional, beyond that is
`Future.md`. A roadmap with equal detail at every horizon is a roadmap that has stopped distinguishing between what
is known and what is hoped.

**Carry the non-goals forward.** Something excluded in Move 5 does not become included by reaching V2 — it becomes
reconsiderable, if it had a reconsider trigger. That distinction is what stops scope creep arriving as a version
number.

**Note where V2 changes the architecture.** If a likely direction requires a different data model or a multi-tenant
change, `09-technology` should know now. Knowing a direction is different from building for it, and only the first
is free.

**Do not size or date it.** The framework cannot produce durations, as `Timeline.md` sets out, and a dated V2
becomes a commitment nobody agreed to.

---

# Where It Misleads

**V2 becomes the promise made to close deals.** Committing to a direction in a sales conversation converts a
candidate into an obligation, and it is made before any evidence has selected it.

**It functions as a scope release valve.** Anything argued about gets deferred to V2, which resolves the argument and
records nothing. The deferral ledger requires a reason and a trigger for exactly this.

**Detailed V2 planning is mistaken for strategic thinking.** It is the least reliable planning in the roadmap, since
it is furthest from evidence. Effort spent specifying it is effort not spent on the MVP's question.

**Architecting for V2 now is justified as foresight.** `09-technology`'s architecture-inflation guard applies:
building for an unselected direction is speculative complexity, paid for immediately.

**Two directions get pursued together.** Two segments or two problems at V2 halves the resource on each, and the
evidence for neither has arrived yet.
