# Learning Objectives

---

# Overview

> After this module you should be able to generate options that could beat your
> preferred one, choose between them on stated criteria, and write down what you will
> not build.

---

# Knowledge Objectives

You should understand:

- What makes options differ in kind rather than in detail
- How a weighted comparison works, and how weights encode judgment
- What an MVP is for: learning something specific, not shipping a small version
- The difference between a non-goal and a deferred item
- What a risk register requires — likelihood, impact, mitigation, and an owner
- What **confidence laundering** is and why it is invisible in the output
- How a declared shortfall from module 04 changes the weighting here

---

# Thinking Objectives

The shift is from *what should we build* to *what are we choosing between, and on what
basis*.

Instead of asking:

> "What is the best solution?"

ask:

- What are three genuinely different ways to address the top-ranked problem?
- Which of these survives the problem turning out to be wrong?
- What would each cost to be wrong about?
- What am I explicitly deciding not to do?
- What does the MVP need to teach me, and what is the smallest thing that teaches it?

---

# Skill Objectives

You should be able to:

- Generate options that differ structurally — build, deliver, partner, do nothing
- Build a weighted comparison and state why each weight is what it is
- Draw an MVP cut line and record the reasoning
- Write non-goals that are genuinely tempting
- Register risks with all four fields, including an owner
- Weight a declared shortfall so that it changes the outcome
- Sequence a roadmap around what must be learned first

---

# Analytical Objectives

You should develop the ability to:

- Notice when three options are one option in three costumes
- Detect a weighting chosen to produce a known winner
- Tell a risk from a fear — a risk has a likelihood and a mitigation
- Recognize an MVP that is a small product rather than an experiment

---

# Judgment Objectives

**How to weight.** Weights are where judgment enters a comparison legitimately. The
discipline is stating the reason for each weight before scoring — "survives if the
problem is wrong" weighted ×3 because module 04 declared a shortfall is a defensible
weight; the same weight applied silently is not.

**Where to cut.** An MVP cut line is drawn at the smallest thing that produces the
learning the run most needs. Cutting to what is quickest to build produces a small
product that teaches nothing.

---

# You Have Learned This When

| Signal | What it indicates |
| --- | --- |
| Your options include one you would be disappointed to pick | They are real options |
| You set weights before scores | The comparison can surprise you |
| Your non-goals are things you want to build | They are doing work |
| A declared shortfall visibly changes your choice | The chain is carried, not filed |
| Your MVP is described by what it will teach you | It is an experiment rather than a version |

---

# What This Module Does Not Teach You

It does not teach specification — module 08 does. It does not teach delivery
sequencing beyond the roadmap's shape; module 10 does that. It does not teach you
whether the business works; module 06 set those constraints and this module chooses
inside them.

---

> **Objectives Principle**
>
> The skill is making a choice that could have gone the other way.
>
> Everything else here — the options, the weights, the scoring — is machinery for
> keeping that possibility open long enough to use it.
