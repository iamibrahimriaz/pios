# Learn — Strategy

---

# What This Layer Is

The human curriculum for the Strategy module. An executing agent does not read it.

---

# What the Module Does

It chooses what to build, in what order, and what deliberately not to build. It
produces solution options, a chosen approach, an MVP definition, non-goals, a risk
register, and a roadmap.

This is the hinge of the framework. Modules 01 through 06 describe; modules 08 through
14 commit. This is the only module that decides.

---

# The Three Requirements That Make It Work

**At least three options before one is chosen.** Not three variants of the same idea —
three approaches that differ in kind. The point is not to demonstrate diligence; it is
that a comparison needs something to compare against.

**The choice justified against the ranked problems, not preference.** Module 04's
ranking is the criterion. A choice defended by taste can be correct and cannot be
checked.

**Explicit non-goals.** What you will not build is the part of a strategy that does
work. Everything else is aspiration.

---

# The Named Failure

This module names one characteristic failure: **confidence laundering** — a choice made
on instinct and then documented as though it had emerged from the comparison. The
options are real, the scoring is real, and the winner was decided before any of it.

It is undetectable in the output. The only defense is generating options you would
genuinely be willing to lose to, and scoring the axes before looking at the totals.

---

# Where a Declared Shortfall Lands

If module 04 declared a shortfall, this is where it must be weighted. In the worked
example threaded through the resources layer, an empty verified-problem list caused
"survives if the problem is wrong" to be weighted triple — and that weighting is what
selected a service-first approach over the AI product the run started with.

> A shortfall that does not change the comparison here was filed, not carried.
