# Best Practices

---

# Overview

The difference between a competent market analysis and a poor one is rarely effort. It is
a small number of habits, applied consistently.

---

# 1. Write the Exclusions First

Most analysts define a market by listing what is inside it. Start with what is outside.

Exclusions force the boundary to be real. "Not hospital EMRs, because the buyer is a
procurement committee rather than a clinician" does more work than three sentences
describing what is included.

---

# 2. Name the Category the Way Practitioners Do

Search in the operator's vocabulary, then in the domain's. They are rarely the same, and
the domain's terms return better sources.

Record the vocabulary. Every downstream module searches better for having it.

If the domain has no name for the category, that is a finding worth stating — an unnamed
category often means an unfunded one.

---

# 3. Size the Segment You Will Actually Sell To

The instinct is to size generously, because a large number feels like a stronger case.

It is not. A large TAM for a population you cannot reach produces a strategy aimed at
people who will never buy. A small, accurate SOM produces a plan that can be executed.

The useful number is the one you could go and act on this quarter.

---

# 4. Put the Price Assumption on the Page

Every bottom-up sizing contains a price. It is usually the least evidenced input and the
one that moves the result most.

Write it explicitly, tag it, and name it as the load-bearing assumption. Do not let it
hide inside the arithmetic.

---

# 5. Read the Regulation, Not the Summary

Summaries of regulation state that a regime applies. The regulation itself states what it
requires.

Module 09 needs the requirements. Getting them now, from the source, is cheaper than
getting them later from someone who has already designed a schema.

---

# 6. Date Every Snapshot

Vendor pricing, competitor counts, and regulatory status all change.

`[verified: vendor pricing page, accessed 2026-03-14]` remains useful in a year because a
reader knows how stale it is. `[verified: vendor pricing page]` does not.

---

# 7. Search for the Failure, Not Just the Opportunity

If nobody serves a segment, somebody probably tried. Find them.

An abandoned competitor is the cheapest lesson in the entire run — the experiment was
already paid for by someone else. Search for shutdown notices, acquisition
announcements, and dormant projects, not only for active products.

---

# 8. Run the Query Backwards

Searching "«market» growth opportunity" returns material written to persuade.

Search "«market» consolidation", "«market» pricing pressure", "why «category» startups
fail". The unfavorable evidence exists, but it will not arrive unless it is asked for.

---

# 9. Treat One Analyst Figure Cited Five Times as One Source

Trade press recycles. Five articles quoting the same projection is one source with four
echoes.

Follow citations back to the original before counting a claim as corroborated.

---

# 10. Record Disagreement Rather Than Resolving It

When top-down and bottom-up disagree materially, the temptation is to pick one and move on.

Record both, state which is more trustworthy here and why, and let the reader see the
spread. A range with a reason is more honest than a point estimate with none.

---

# 11. Keep the Regulatory Section Actionable

Write it as though the reader is an engineer designing a schema, because eventually one
will be.

| Weak | Strong |
| --- | --- |
| "GDPR applies." | "GDPR applies because personal data of EU residents is processed. Requires: lawful basis recorded per processing purpose, data subject access response within 30 days, erasure capability, and EU-region storage unless an adequacy decision covers the destination." |

---

# 12. Stop at the Boundary of the Module

When a competitor's feature set becomes interesting, stop. Write the name in a note for
module 05 and return to the market.

Module 05 will do that work with segment and problem context that this module does not
have. Doing it early means doing it twice, and worse the first time.

---

# 13. State What You Could Not Establish

A section that reads "practice count could not be verified; estimated from population
ratio; tagged as assumption; validate before pricing decisions" is a working analysis.

The same section with an invented registry citation is a liability that will not be
detected until someone tries to use the number.

---

# 14. Finish With the Inversion

Before the gate, ask: *if this market were a bad place to build, what would the evidence
look like?*

Then check whether that evidence is present in what you already found. It often is,
recorded but not weighted.

---

# Anti-Practices

| Habit | Why it fails |
| --- | --- |
| Sizing before bounding | The number measures nothing |
| Quoting a TAM without checking its boundary | Measures a different market |
| Presenting a figure with no derivation | Cannot be challenged, so cannot be trusted |
| Reporting only supportive trends | Produces a case, not an analysis |
| Asserting a gap with no reason | Usually imaginary |
| Regulatory findings as acronyms | Useless to module 09 |
| Undated snapshots | Unusable within a year |
| Filling gaps with plausible citations | Destroys trust in every other claim |

---

# Self Assessment

- Did I write the exclusions before the inclusions?
- Is the price assumption visible and tagged?
- Did I read the regulation or a summary of it?
- Did I search for what failed here, not only what exists?
- Did I follow recycled citations back to the original?
- Did I run the inversion before the gate?

---

> **Practice Principle**
>
> The quality of a market analysis is measured by how easy it is to disagree with.
>
> Make every number, every source, and every assumption visible enough to attack.
