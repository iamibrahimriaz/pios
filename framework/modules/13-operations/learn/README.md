# Learn — Operations

---

# What This Layer Is

The human curriculum for the Operations module. An executing agent does not read it.

---

# What the Module Does

It plans how the product is run, supported and kept compliant after launch. It produces
a support model, runbooks, an incident process, compliance operations, and a cost model.

It is the last module in the delivery line and the one that most often produces a
regression — because it is where the framework's arithmetic finally closes.

---

# The Named Test

**The 3am test.** Could a stranger follow this runbook at three in the morning, without
you, without asking a question?

That standard produces a specific structure: access needed at the top, because a
credential is the usual blocker; three columns — step, expected, if different — so the
follower does not have to diagnose; a verification at the end; and a "do not do" line,
because every system has one tempting action that makes things worse.

---

# The Third Arithmetic Check

This is the cumulative one. Infrastructure from module 09, inference from module 14,
support hours, compliance hours, and — the line most often omitted — **the operator's own
time at a real hourly rate.**

> A cost model that prices the founder's hours at zero is why the third check passes on
> products nobody can afford to run.

A breach is a **regress** to module 06 for the price or module 07 for the scope. It is
never absorbed by revising the forecast the plan just stated. In the worked example the
ceiling is exceeded and the run regresses — which is the framework doing its job, not
failing.

---

# Where the Obligation Chain Ends

Module 02 found the obligation. Module 09 built the mechanism. This module gives it a
**cadence, a named owner, evidence produced, and a location for that evidence.**

"The team" is not an owner. Being compliant and being able to show you were compliant are
different achievements, and only the second survives an audit.
