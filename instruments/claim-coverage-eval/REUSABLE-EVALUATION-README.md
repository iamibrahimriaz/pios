# Claim-Coverage Evaluation

**A reusable instrument for measuring how much of what a document *asserts* survives being reduced
to a handful of its own sentences — and whether a language model earns its place in that reduction.**

**Self-contained. It assumes no product, no audience, no price, and no hypothesis.**

---

## 1. What this measures

**One number, and it is deliberately narrow:**

> **`C_a` — the fraction of a document's author-stated claims that a reader could state and defend
> having seen only a short verbatim extract of that document, and nothing else.**

Measured for **two selectors on the same corpus**, so the comparison is like-for-like:

| Arm | Selector | Answers |
| --- | --- | --- |
| **1** | **Model-guided** — one fixed instruction, applied unchanged to every document | Can a model pick the load-bearing sentences? |
| **2** | **Mechanical** — TextRank-style, scripted, no model, no network, no vendor | **Is the model doing anything a cheap algorithm cannot?** |

**The gap between the two arms is the point.** It prices the model in the only currency that matters
for this decision: content actually recovered.

**Two secondary outputs**, both free once the corpus exists:

- **Verbatim containment** — whether extracted sentences can be located in the source by exact
  search. This is the feasibility test for any *anchoring* or *citation-to-source* feature.
- **Normalization sensitivity** — how much of an apparent containment failure is typographic
  rather than semantic. **In the reference run this was 100% of it.**

---

## 2. When to use it

**Use it when a design hinges on "can we just show the source sentences?"** — provenance-linked
summaries, citation-grounded answers, extract-first readers, retrieval snippets, quote verification,
or any feature where an extractive fallback is a candidate.

**Use it before committing to a generative step**, because it is the cheapest way to learn whether
the generative step is load-bearing or decorative.

**Do not use it** to establish that anyone wants the feature, would use it twice, or would pay for
it. **It measures an artifact, not a market.** §7.

---

## 3. Required inputs

| Input | Requirement | Why |
| --- | --- | --- |
| **Documents** | ≥ 10, from ≥ 3 independent sources | Fewer sources measures one house style |
| **Ground truth** | **3–5 discrete claims per document, authored by someone other than the evaluator** | §8. This is the requirement people break |
| **A fixed selection rule** | Written once, applied to every document, **zero per-document overrides** | An overridden rule measures the operator |
| **Length spread** | Include long documents deliberately | Length is the dominant driver of coverage; a short-heavy corpus inflates the headline |
| **A grading rule** | Binary, no partial credit, written before grading | §5 |

**The reference corpus already satisfies all of these** and can be reused directly, or replaced.

---

## 4. Reproducing the reference evaluation

```bash
python3 scripts/rebuild_corpus.py            # fetch 12 pinned PMC articles -> corpus/body/
python3 scripts/rebuild_corpus.py --verify   # confirm SHA-256 of every body against the manifest
python3 scripts/mechanical_selector.py       # regenerate arm 2 from scratch
python3 scripts/verify_and_score.py          # containment + coverage for both arms
```

**Expected:** 12 documents · 50 claims · **arm 1 = 68.0%** · **arm 2 = 28.0%** · containment 60/60
and 60/60.

**The corpus is pinned by identifier, not by search query.** The original discovery used a
relevance-ranked search, which is not reproducible; `corpus/screening-log.txt` preserves all 77
screening decisions for provenance, and `rebuild_corpus.py` pins the twelve that survived.

**`corpus/truth/` is committed and never regenerated by any script.** Regenerating the answers from
a script that a later edit could change is how an evaluation quietly starts grading itself.

### Running it on your own corpus

1. Replace `corpus/body/*.txt` and `corpus/truth/*.txt`, keeping the numbering.
2. **Re-derive your own thresholds first** (§6) — do not inherit the reference bands.
3. Run arm 2 with `mechanical_selector.py` unchanged.
4. For arm 1, read each body **with the truth files closed**, emit five sentences, verify with
   `verify_and_score.py`.
5. Grade, then score. **Record counts before interpreting anything.**

---

## 5. Grading rule

**"Recoverable" means: a reader who saw only that extract, and nothing else, could state this claim
and defend it.** Not "hints at". Not "you would guess".

- **Binary. No partial credit.** Partial credit is where generous grading enters.
- **Conjunctive claims require every part.** *"Star-shaped polycaprolactone nanoparticles"* scores
  **N** when the extract says only *"polycaprolactone nanoparticles"*.
- **When you hesitate, the answer is N.** Write this down before starting, because you will hesitate
  around row 60.

**The reference grading is strict.** A laxer reading raises both arms roughly proportionally and
moves neither band. **Strictness was chosen because it runs against the result the grader expected
to want** — see §9.

---

## 6. Interpreting the result

### The comparison first, the absolute number second

| Pattern | Reading |
| --- | --- |
| **Both arms high, small gap** | Extraction works and the model adds little. **The cheap selector is the product** |
| **Both arms low** | Short verbatim extraction is the wrong unit for this material. Change the unit, not the selector |
| **Large gap, arm 1 high** | The model is load-bearing. **Its cost is now a required line in the business case, not an optimization** |
| **Large gap, arm 2 near zero** | Inspect *what* arm 2 selected before concluding anything (§10) |

### The absolute bands

**The reference run used ≥70% / 50–69% / <50%.** Those came from one project's bar — *"if three
claims in ten are missing, the reader must open the document anyway, so the tool saved nothing."*

> **That is a product judgment, not a property of the instrument. Re-derive it from your own
> tolerance before use, and write it down before you look at any result.**

**Pre-register whatever bands you choose**, along with a sample floor and a statement of what result
would make you wrong. Thresholds moved after seeing a number are not thresholds.

---

## 7. What it cannot establish

| Not measured | Why |
| --- | --- |
| **Demand** — that anyone wants this | Coverage is a property of an algorithm |
| **Frequency or severity** of the underlying problem | Nothing here observes an incident |
| **Willingness to pay** | Not one rung of any WTP ladder is touched |
| **Retention** | Nothing here observes a second use |
| **Any individual's preference** | The instrument measures recovery against stated claims, not what a reader enjoys |
| **Faithfulness of generated prose** | Containment proves *provenance*, never *accuracy* |
| **Generalization beyond your document type** | The corpus is what it is |

> **A high score buys the right to run a test with people in it. It is not that test.**

---

## 8. Avoiding ground-truth contamination

**This is the failure that silently invalidates the whole evaluation.**

> **If the person writing the ground truth also picks the sentences, coverage approaches 100% by
> construction and measures their memory.**

**Four defences, in order of strength:**

1. **Use externally authored ground truth.** The reference corpus uses each paper's
   `author-highlights` — 3–5 discrete claims written by the paper's own authors, published before
   the evaluation existed. **This removes the problem rather than managing it.**
2. **Withhold it structurally.** Bodies and truth go to separate directories; selection happens with
   the truth files unopened. Not a promise — a directory layout.
3. **Strip summaries from the body.** The reference builder removes abstracts, highlights, methods
   and declarations, so the task cannot be solved by locating a summary. **Otherwise you are testing
   whether the selector can find an abstract.**
4. **If you must author it yourself:** write claims in your own words from the document, never by
   copying or paraphrasing-from-sight any sentence; commit them to version control **before**
   generating any extract; and never edit them afterwards.

**Also fix the selection rule in advance and never override it.** Record the override you wanted to
make; do not make it. An overridden rule is judgment wearing a procedure's name.

---

## 9. Handling extractive vs. model-guided comparisons

**Run both arms on the same corpus, the same claims and the same grading rule.** A model arm scored
against a different corpus is not a comparison.

**Three asymmetries to hold on to:**

- **The model arm's score includes the model's cost.** If the cheap arm is the reason a design was
  affordable, the model arm's number does not rescue it — it reintroduces the cost the design
  existed to avoid.
- **Grading a self-run comparison is not neutral.** If the grader has a stake in one arm winning,
  **cap the result in advance**: declare that a self-graded arm may return a negative or
  inconclusive verdict but never a passing one. A favourable number from a favourable grader cannot
  clear a bar; an unfavourable one is informative. **The reference run applied this cap.**
- **Do not simulate participants.** If a question needs a human preference, this instrument does not
  answer it, and generating example judgments is not a substitute.

## 10. Unicode normalization and equivalent text

**Across 120 sentence checks in the reference run, exactly one raw containment failure occurred, and
it was a curly apostrophe** — `conductance’s` (U+2019) emitted as `conductance's` (U+0027).
**Zero failures survived normalization.**

> **A byte-exact anchor check will report false failures on ordinary published prose.**

**Before comparing, normalize both sides to NFC and fold:**

| Class | Fold |
| --- | --- |
| Quotes | `’ ‘` → `'` · `“ ”` → `"` |
| Dashes | `– — −` → `-` |
| Spaces | non-breaking, thin, narrow, zero-width → ` ` or removed |

**Do not fold case, digits, or whitespace inside code and formulae** — there the difference is the
content. `scripts/verify_and_score.py` reports raw and folded containment separately, and the gap
between them is the diagnostic. `results/unicode-normalization-case.json` preserves the original
failing string so the finding stays testable.

## 11. Reusable methodology vs. originating-project decisions

**This instrument was extracted from a product research run. The boundary is drawn explicitly so
nothing project-specific travels with it.**

| Reusable — no project assumptions | Originating-project decision — **re-derive or discard** |
| --- | --- |
| The coverage measure `C_a` and its definition | **The 70% / 50% bands.** §6 |
| The two-arm model-vs-mechanical design | The conclusion that a particular product should not be built |
| Externally-authored ground truth as the contamination fix | The choice of scientific papers as the document type |
| The blind-selection directory layout | The 12-document corpus size (a floor, not a target) |
| The strict binary grading rule | Any pricing, audience, or channel judgment — **none is present here** |
| Verbatim containment + normalization testing | A separate preference measure the originating run defined but never ran, because it required participants |
| The self-graded-arm cap (§9) | |
| Pre-registration discipline: floors and thresholds before collection | |

**Nothing in `corpus/`, `selections/`, `results/` or `scripts/` references the originating product.**
`PROVENANCE.md` records where this came from, what the originating run concluded, and why — kept
separate so it can be read as history rather than as an assumption.
